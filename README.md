# xray-enhance-gl

Image enhancement for X-ray-like images in **C++17 and GLSL**: window/level and other intensity mappings,
histogram equalisation, histogram matching, CLAHE, noise reduction, sharpening and local contrast. Every
shader is tested against a plain C++ version, and the methods are compared on projections of public CT scans.

This is a study project on public data. It is not a medical device and has not been evaluated by clinicians.

## What is inside

| operation | GPU code | idea |
|---|---|---|
| window/level, sigmoid, automatic window | `window_level.frag` + histogram percentiles | choose which intensities fill black to white |
| histogram | `histogram.comp` | compute shader with atomic counters, whole image or per tile |
| equalisation, histogram matching | `lut.frag` | table built from the cumulative histogram |
| CLAHE | `clahe.frag` | clipped per-tile tables, blended between tile centres |
| Gaussian | `gaussian.frag` | two one-direction passes |
| bilateral | `bilateral.frag` | smooths noise, mostly keeps strong edges |
| unsharp mask | `unsharp.frag` | adds back fine detail |
| adaptive local contrast | `local_contrast.frag` | stretches detail around the local mean, with a gain limit |

OpenGL 4.3 runs without a window through EGL. Per-pixel filters are fragment shaders drawing into 32-bit float
textures. The histogram is a compute shader.

## Build and test (Linux)

```bash
sudo apt-get install cmake g++ libopengl-dev libgl-dev libegl-dev libegl1 libegl-mesa0 libgl1-mesa-dri doctest-dev
cmake -S . -B build && cmake --build build -j
ctest --test-dir build --output-on-failure -V
```

The command-line tool applies one operation to a greyscale PFM image:

```bash
./build/enhance in.pfm out.pfm clahe 8 2.0
```

## How the shaders are checked

The tests run each shader and its C++ reference on the same image. Histograms must be identical and images must
agree within 0.0001 on a 0 to 1 scale. Property tests cover behaviour that must hold anyway, such as a flat
image staying flat under a blur. The tests print the largest difference for each operation. Both versions
follow the same formulas, so this catches shader mistakes, not a wrong formula.

The tests and the study run on GitHub Actions with **Mesa llvmpipe**, which is OpenGL running on the
processor. **No speed numbers are reported**, because they would say nothing about a graphics card.

## What stands out

Summary of the tables above (unseen subjects).

- **Noise removal helps most when noise is high.** At 2,000 photons the tuned filters raised SSIM from 0.754
  to about 0.96. At 100,000 photons the gain was about 0.01.
- **The bilateral filter did not earn its edge-preserving name here.** At medium and high noise, tuning kept
  choosing the widest brightness range tried (0.32), where it behaves almost like a Gaussian, and the two scored
  about the same SSIM. A likely reason: the mean step across a bone outline is only about 0.03 on the 0 to 1
  scale, close to the noise itself.
- **Sharpening trades noise for edges.** An unsharp mask of strength 1 raised edge strength to 1.24 and the
  noise left from 0.0157 to 0.0294.
- **Window/level makes edges easier to see, not clearer against their surroundings.** An automatic 2-98% window
  raised the on-screen bone-edge step 1.57 times while the step-to-spread ratio stayed at 1.00 times, at the
  cost of 2.1% of pixels clipped.
- **CLAHE traded the other way.** At clip 2 the step rose 1.65 times but the ratio fell to 0.92 times. Filtering
  with the bilateral filter first gave 1.62 times with the ratio at 1.00.
- **Settings tuned at one noise level did not carry over.** The filter tuned at low noise scored SSIM 0.845 at
  high noise, against 0.962 for the filter tuned there. Moving settings between thorax and pelvis changed SSIM
  by at most 0.018.
- A few pixels in the thickest views exceed the fixed display scale and are clipped (at most 2.7% of any
  projection).

## Limitations

- The images are **parallel projections of CT scans**, not real X-rays or cone-beam geometry. Noise is a
  Poisson photon model, with no scatter or detector effects.
- The measures stand in for visibility. No radiologist or radiotherapy staff judged any image.
- A pixel that receives no photon is counted as one photon, so at higher noise the thickest body parts level
  off at a maximum value.
- Bone outlines come from the dataset's segmentations, projected and thresholded.
- A small number of subjects from one public dataset, in two body regions.
- Data is read back to the processor after each step so it can be tested. A viewer would keep it on the
  graphics card.
